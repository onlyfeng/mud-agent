# Changelog

All notable changes to this project will be documented in this file.

## [Unreleased]

### Changed (game profile layer, 2026-10-17)

- Server-specific text semantics moved out of the core into a per-game **profile** (`src/core/game-profile.ts`): HP/MP/level/gold patterns and the status-refresh command, exit lines and splitter, room-name heuristics, item lines and the pick-up reply, combat start/end, exploration event types, text triggers, noise rules (ambient chat, movement, emotes, login prompts, inline ASCII ids) and the direction reverse/alias tables. The parser, text analyzer, noise filter, triggers and both autopilot strategies read the active profile; nothing in the core knows any server's wording. Lookup order: `<session>/profile.json`, then `<storage root>/profiles/<server.host>.json` (the root is passed to child processes as `MUD_STORAGE_ROOT`), else the bundled default (shipped as `profiles/example.json`, a Chinese LPMud family example, not a universal rule set). A profile merges onto the default section-by-section (arrays replace); an invalid file makes the daemon refuse to start with the offending key instead of silently falling back. The numeric HP triggers (`hp_critical` / `hp_low`) and the user's decision vocabulary (continue / stop / back / pick-up negation) stay in the core — they are the agent's own semantics, not the server's.
- Max-HP continuity inference removed: the `characterLevel` baseline, level-up detection and the character-level allow-lists are gone. A maximum is established only by a two-value sample; a current-only sample (including a ROM-style `<N hp>` prompt trailing a status reply) keeps the known maximum while the current value fits under it and marks it unknown once exceeded. A two-value sample is timestamped (`maxHpSampledAt`); a health baseline with no sample yet (right after login), an unknown maximum, no timestamp or one older than 5 min is untrusted. While it is untrusted the autopilot sends the profile's status query (`status.query`, at most once per 20 s, through its own send-queue path) and skips strategy actions until a fresh two-value sample arrives (the strategies treat a missing maximum as full health); a lost query keeps it waiting rather than trusting the old maximum. The daemon's HP triggers keep using the maximum they have: the maximum only changes through player activity, and activity brings new samples (the driving model issues status commands in companion mode, the autopilot refreshes in automatic modes), so a stale-but-unchanged maximum while idle is better than no HP alert at all. Unknown keys anywhere in a profile file are rejected with their path.

### Fixed (standalone-repo review follow-ups, 2026-10-17)

- `mud-ctl`: `--session` / `--session-key` without a value now fails with exit code 2 instead of silently falling back to the root runtime directory; read-only actions (`status`, `state`, `read`, `read-since`, `alerts`, `config-show`, `report`, `decisions`, `autopilot status`) no longer register a session directory, so a mistyped key cannot turn an ordinary topic into a routed MUD session.
- `mud-ctl start` (stale autopilot cleanup) and `mud-ctl restart` respawn the autopilot after the new daemon starts when `game-mode.json` is still semi-auto / full-auto, instead of leaving the session marked automatic without a process.
- `set-mode semi-auto|full-auto` (`mud_admin`, `/mud mode`) is rejected while the daemon is not running.
- `acquirePidLock` reclaims a dead-PID lock through an atomic `rename` claim and puts a lock back if another process replaced it in between, so two concurrent starts cannot both win.
- Model-route hook tracks every overridden `runId` (bounded set) instead of the latest one per session, so interleaved runs of one session each keep their fallback chain.
- Subagent policy (`completionTarget` stripping, `sessions_yield` block) is gated on an active MUD session (daemon alive), not on directory existence.
- `parseState` keeps a known `maxHp` / `maxMp` on current-only samples that fit under it (clears it only when exceeded); `resetRuntimeState` also clears last run's HP / MP / exits / location so a fresh autopilot never acts on stale gauges.
- Logger keeps its byte counter when a rotation fails (only `ENOENT` resets), so a persistently failing rotation cannot grow the file unbounded.
- Full-auto pause-event notifications (long combat, etc.) are rate-limited per event type (60 s).
- Queued-message detection inspects both `currentUserMessage` and `prompt`.
- The daemon records a drain timestamp per queued request (`drains[<enqueue time>]`, last 20); `mud_act` uses its own request's stamp so two batches drained before it polls cannot skew its cursor.
- `package.json` `files` now includes `src/`, `scripts/` and `tsconfig.json` so `npm run install:runtime` and `normalize:sessions` work from a packed install.
- Follow-up review: `mud-ctl autopilot stop` re-reads the mode generation after publishing the stop and re-tags it until stable (`publishExplicitStop`), so a `set-mode` racing with the stop cannot make the later stop look superseded; `/mud status` and `/mud stop` no longer register a session; `start` / `restart` re-read `game-mode.json` right before each respawn attempt and cancel when the mode is no longer automatic; stale PID-lock reclamation is serialized through a `<pid>.reclaim` O_EXCL lock and re-verifies the dead pid before unlinking, so a live lock is never renamed or deleted.

## Known limits

Review findings deliberately not addressed in this change set (each one is reachable only outside the deployed configuration — a single Chinese-language session on one Telegram topic — or belongs to a follow-up redesign). Each is answered in its review thread with the same reasoning.

- How a given server writes HP, levels, exits, combat or events is a profile concern (`profile.json`), iterated in play by the driving model; the core ships one example profile and makes no claim about other servers. Max-HP is never inferred from text any more (see Changed above).
- Session-directory resolution on a cache miss still runs the synchronous v1→v2 migration pass; while an in-process async launcher holds the maintenance lock and a live deferred v1 directory still exists (rolling upgrade from the pre-v2 layout), a concurrent gateway command can stall up to the 2 s lock timeout. Steady state (no v1 directories) never takes the lock on that path.
- Stop is polled, not linearised with the send queue: the autopilot adjudicates a pending stop at the top of each tick and again while holding the queue lock just before it writes, but a stop published in the microseconds between that check and the write can still let the one command already decided through; the stop is honoured on the next tick (at most one `loopInterval`). Making stop publication take the send-queue lock would couple the gateway's control-file write to the queue for no observable gain.
- The daemon does not issue game commands on its own: in companion mode the HP triggers use whatever maximum the last two-value sample established, so a maximum that changed without any status command afterwards (a level-up right before going idle) is reflected only once the next status command is sent. Letting the daemon inject its own status queries was tried and removed — its replies interleave with `mud_act` response windows, reset the idle timer and survive reconnects into the login handshake.
- Free-text decision choices (the user's replies on the channel) are matched by keyword with negation taking precedence; the supported vocabulary is the options each decision lists (plus their numbers). Other phrasings are best-effort only. This is the agent's own vocabulary, so it stays in the core rather than in a profile.
